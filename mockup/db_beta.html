Sistema de Facturación

Documentación del modelo de base de datos PostgreSQL

1. Descripción general

Esta base de datos administra el sistema de facturación del gimnasio. Permite registrar clientes, empleados, productos vendidos, facturas, detalles de factura, planes de membresía, membresías adquiridas y eventos.

Decisión de diseño: los productos físicos y los planes de membresía se manejan como entidades independientes.

3. Tabla: CLIENTES

Almacena la información personal y de contacto de los clientes del gimnasio.

Campo Tipo Restricción Descripción
id_cliente SERIAL PK Identificador único del cliente.
nombre VARCHAR(100) NOT NULL Nombre del cliente.
apellido VARCHAR(100) NOT NULL Apellido del cliente.
cedula VARCHAR(20) UNIQUE, NOT NULL Número de identificación.
fecha_nacimiento DATE NULL Fecha de nacimiento.
correo VARCHAR(150) NULL Correo electrónico.
telefono VARCHAR(30) NULL Número telefónico.
genero VARCHAR(30) NULL Género registrado.
contacto_emergencia VARCHAR(150) NULL Contacto para emergencias.
contrato_ruta VARCHAR(150) NULL Información relacionada con contrato/ruta.
vigente_hasta DATE NULL Fecha de vigencia registrada.
fecha_registro TIMESTAMP NOT NULL Fecha y hora de registro.

4. Tabla: EMPLEADOS

Registra a los empleados que utilizan el sistema. El empleado es quien genera la factura y realiza el cobro.

Campo Tipo Restricción Descripción
id_empleado SERIAL PK Identificador del empleado.
nombre VARCHAR(100) NOT NULL Nombre.
apellido VARCHAR(100) NOT NULL Apellido.
usuario VARCHAR(50) UNIQUE, NOT NULL Usuario utilizado para iniciar sesión.
password VARCHAR(255) NOT NULL Contraseña almacenada de forma segura.
rol VARCHAR(30) NOT NULL ADMIN, SUPERVISOR o VENDEDOR.
activo BOOLEAN NOT NULL Indica si el empleado está activo.
fecha_registro TIMESTAMP NOT NULL Fecha de registro.

5. Tabla: PRODUCTOS

Contiene los productos físicos que pueden ser vendidos mediante una factura.

Importante: por ahora esta tabla no administra inventario. Por esa razón no contiene campos de stock. Tampoco se utiliza un campo tipo.
Campo Tipo Restricción Descripción
id_producto SERIAL PK Identificador del producto.
nombre VARCHAR(150) NOT NULL Nombre del producto.
categoria VARCHAR(100) NOT NULL Categoría del producto.
precio NUMERIC(10,2) NOT NULL Precio de venta.

7. Tabla: FACTURAS

Registra cada factura generada por un empleado para un cliente. La factura puede contener productos y puede originar una membresía.

Campo Tipo Restricción Descripción
id_factura SERIAL PK Identificador interno.
numero_factura VARCHAR(30) UNIQUE, NOT NULL Número visible de la factura.
id_cliente INTEGER FK, NOT NULL Cliente al que pertenece la factura.
id_empleado INTEGER FK, NOT NULL Empleado que genera la factura.
fecha TIMESTAMP NOT NULL Fecha y hora de emisión.
metodo_pago VARCHAR(30) NOT NULL Método utilizado para pagar.
descuento_porcentaje NUMERIC(5,2) NOT NULL Porcentaje de descuento aplicado.
subtotal NUMERIC(10,2) NOT NULL Subtotal antes de impuestos.
iva NUMERIC(10,2) NOT NULL Valor monetario del IVA.
total NUMERIC(10,2) NOT NULL Total final de la factura.
estado VARCHAR(30) NOT NULL EMITIDA o ANULADA.
motivo_anulacion VARCHAR(255) NULL Motivo registrado cuando una factura es anulada.

8. Tabla: DETALLE_FACTURA

Representa los productos individuales incluidos dentro de una factura. Permite que una factura tenga uno o varios productos.

Campo Tipo Restricción Descripción
id_detalle SERIAL PK Identificador del detalle.
id_factura INTEGER FK, NOT NULL Factura a la que pertenece.
id_producto INTEGER FK, NOT NULL Producto vendido.
cantidad INTEGER NOT NULL Cantidad vendida.
precio_unitario NUMERIC(10,2) NOT NULL Precio del producto al momento de la venta.
subtotal NUMERIC(10,2) NOT NULL Subtotal del detalle.
Importante: se almacena precio_unitario en el detalle para conservar el precio histórico utilizado en la factura aunque posteriormente cambie el precio del producto.

9. Tabla: MEMBRESIAS

Representa una membresía concreta adquirida por un cliente. El plan define las condiciones comerciales y esta tabla registra la instancia real de dicha membresía.

Campo Tipo Restricción Descripción
id_membresia SERIAL PK Identificador de la membresía.
id_cliente INTEGER FK, NOT NULL Cliente propietario.
id_plan INTEGER FK, NOT NULL Plan utilizado para configurar la membresía.
id_factura INTEGER FK, NOT NULL Factura que originó la membresía.
fecha_inicio DATE NOT NULL Inicio de la membresía.
fecha_fin DATE NOT NULL Finalización de la membresía.
dias_totales INTEGER NOT NULL Cantidad total de accesos disponibles originalmente.
dias_restantes INTEGER NOT NULL Cantidad de accesos que todavía puede utilizar el cliente.
estado VARCHAR(30) NOT NULL ACTIVA, VENCIDA o CANCELADA.
id_membresia_pareja INTEGER FK, NULL, UNIQUE Referencia a la membresía de la pareja.
Control de accesos: en los planes PASES, dias_totales representa la cantidad de accesos adquiridos y dias_restantes representa la cantidad de accesos disponibles. Cada ingreso del cliente reduce dias_restantes en uno.
Membresía de pareja: el plan Senior Pareja cuesta $111 para dos clientes. Se pueden registrar dos membresías relacionadas entre sí, utilizando id_membresia_pareja.

10. Tabla: CATEGORIAS_EVENTO

Contiene las categorías utilizadas para clasificar los eventos del gimnasio.

Campo Tipo Restricción Descripción
id_categoria SERIAL PK Identificador de la categoría.
nombre VARCHAR(100) UNIQUE, NOT NULL Nombre de la categoría.
color VARCHAR(30) NOT NULL Color utilizado para representar la categoría.

11. Tabla: EVENTOS

Registra las actividades o eventos programados en el gimnasio.

Campo Tipo Restricción Descripción
id_evento SERIAL PK Identificador del evento.
titulo VARCHAR(150) NOT NULL Nombre del evento.
id_categoria INTEGER FK, NOT NULL Categoría del evento.
fecha DATE NOT NULL Fecha del evento.
hora_inicio TIME NOT NULL Hora de inicio.
hora_fin TIME NOT NULL Hora de finalización.
descripcion TEXT NULL Descripción del evento.
cupo_maximo INTEGER NULL Cantidad máxima de participantes.

12. Reglas de negocio principales

  • Una factura pertenece a un cliente y es generada por un empleado.
  • Una factura puede contener uno o varios productos.
  • El precio registrado en DETALLE_FACTURA representa el precio histórico utilizado en la venta.
  • Los productos físicos no representan membresías.
  • Los planes de membresía se administran mediante PLANES_MEMBRESIA.
  • Una membresía pertenece a un cliente y utiliza un plan.
  • Una membresía queda asociada a la factura mediante id_factura.
  • El descuento variable de Junior se aplica en la factura, no modificando el precio base del plan.
  • El plan Senior Pareja permite relacionar dos membresías.
  • Los planes PASES representan duraciones de 1, 5 y 10 días.
  • El plan Senior de larga duración es de 90 días.
  • En los planes PASES, cada acceso utilizado reduce dias_restantes en uno.
  • Cuando dias_restantes llega a cero, el cliente no puede utilizar nuevamente ese pase.
  • Los productos actualmente no manejan inventario ni stock.

14. Decisiones de diseño

Productos vs. membresías

Los productos físicos y las membresías tienen comportamientos diferentes, por lo que no se almacenan dentro de la misma tabla. Los productos se encuentran en PRODUCTOS, mientras que los planes comerciales se encuentran en PLANES_MEMBRESIA.

Precio histórico

El precio de un producto puede cambiar con el tiempo. Por ello, el precio utilizado en una venta se copia en DETALLE_FACTURA.precio_unitario.

Descuentos

El descuento se registra en la factura porque representa una condición aplicada a una venta específica. El precio base del plan permanece independiente.

Duración de membresías

Los planes pueden tener duración expresada en días o meses. Por ello se utilizan los campos duracion y unidad_duracion.
